## What 1.99 changes

**One gap closed: the shop's crystal-buy table gets its S-Rank row.** Section 12.5's crystal table read E through A only (10 / 40 / 170 / 750 / 3,400 g) while every other Rank-bearing table in the same section — weapon, armor, accessory, key, rune — carried all six Ranks including S. Nothing in the prose marked the omission as deliberate the way Section 12.1's licensed-market table explicitly does (`"S-Rank crystal: Auction-only, no posted price"`). The mined-deposit formula (Section 11.1) has authored S-Rank crystal generation, at a ×32 multiplier, since long before this edge — the shop simply had nowhere to sell what the world already let the Bearer mine.

The gap surfaced the ordinary way this profile's gaps surface: in play, the first time it mattered. The Bearer's first S-Rank instant dungeon produced a mining haul the shop had no price for.

**The derivation.** No number here is invented. The weapon chassis table's A-to-S step is the cleanest ratio in Section 12.5 - exactly **×4.5** (40,000 g -> 180,000 g), repeating a pattern the same table already uses at C-to-D and E-to-D. Applying that multiplier to the crystal row's own A-Rank anchor:

```
3,400 g x 4.5 = 15,300 g
```

**S-Rank crystal, shop buys for 15,300 g.**

## What did not change

**No other row, no other table, no Rank, no XP value, no threshold, no Gate rule.** The E-through-A crystal prices are untouched. The licensed (USD) market's own S-Rank silence (Section 12.1) is a different, deliberate gap and is not addressed here - a Bearer still cannot post an S-Rank crystal to the regulated Chicago market at a fixed rate; this edge governs only the Bearer-only System shop's gold economy.

## Migration procedure

**1. Advance `profile_version` to 1.99** on the campaign's live character sheet, and re-pin `world_rule_profile:` in `090_CAMPAIGN_STARTUP.md`.

**2. No stored figure is recomputed.** No prior sale used this price - the Bearer's first S-Rank crystals were mined and sold in the same session this edge closed. There is nothing to reprice.

**3. A capture restored across this edge needs step 1 and no other treatment.**

**Immutable checkpoints are byte-unchanged.** Any checkpoint captured before this edge keeps what it was captured under; the gap it recorded is historical once this edge exists.
