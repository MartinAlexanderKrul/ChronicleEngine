## What 1.45 changed

**Nothing a character could notice.** 1.45 adds no rule, no number, no cost, no timer, and no capability. It declares one thing, and the thing it declares is about how this world's Events are *written down*, not about what happens in them.

Gatefall opts into the Data Model Section 2.4 `participation_audits` block (Decision 085). The new manifest names two facts:

- **A baseline.** `EVT-000268`. Coverage is prospective from it, so no Event already in the chronicle acquires an obligation and none is rewritten.
- **A coverage set.** Twelve fiction-bearing Event kinds — `social`, `scene`, `combat`, `relationship`, `downtime`, `disclosure`, `discovery`, `exploration`, `work`, `harvest-job`, `shop`, `loot`. Within those, every Character named in an Event's own `participants` needs a recorded result: `record-updated` naming the object the promotion moved, or an explicit `no-change`.

Administrative kinds are deliberately outside coverage — `promotion`, `profile-adoption`, `rules-migration`, `ruling`, and the Section 7.1 settlement kinds. They record bookkeeping about the world rather than something an NPC did in it, and auditing them would buy noise.

**Why this world, and why now.** The rule the audit backs was written because of this campaign: the NPC ledger reached 262 KB and forty-seven objects while nothing required the Runtime to read a record before playing the character it describes. Gatefall is the prototype campaign for Version 0.3 and the world that produced the evidence, so it is the world that carries the first coverage set.

## Compatibility treatment

**1.44 → 1.45 compatibility treatment.** Preserve every stored value and all resolved canon. Adoption requires no recomputation and no state migration.

**No stored field changes.** No pool, Rank, counter, quest, price, timer, item, relationship, or resolved outcome is touched. No roll is rerolled and no scene is reinterpreted. The Section 6.1 tables, Section 12.5.1's elixir rule, and every mechanic 1.44 and earlier authored stand exactly as written.

**Nothing is backfilled.** The 217 Events already in the chronicle carry no `participation_audits` block and never will. The baseline is the campaign's Event high-water mark at adoption, which is what makes this migration free: the obligation begins with the next Event allocated, not with the history.

**The cost is prospective and falls on the writer.** From adoption, a covered Event must state a result for every Character it names. The common entry will be `no-change`, and that entry is not machine-verifiable — it exists so validation can distinguish "nothing moved" from "nobody looked" (Decision 085). The half that is verifiable is `record-updated`: the named object must actually cite the Event, and `tools/validate_repository.ps1` fails the build when it does not.

**Data Model 0.1.5 → 0.1.6** accompanies this adoption, engine-side. The block is additive and optional; live objects are retagged and immutable checkpoints keep their captured schema.

Record adoption as `EVT-000269`; consume no fictional time and reopen nothing. Immutable Profile 1.44-and-earlier checkpoints remain byte-unchanged and run the compatibility chain through 1.45 at readiness.
