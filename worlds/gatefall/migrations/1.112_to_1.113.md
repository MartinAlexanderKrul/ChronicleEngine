## What 1.113 changes

**Section 15.3.1's render grammar only.** No skill's Rank, Mana cost, mastery level, effect text, acquisition route, or any other canonical field changes. What changes is how `/system skills` lays them out:

| Axis | 1.112 | 1.113 |
|---|---|---|
| Top-level grouping | Mechanical: ACTIVE / PASSIVE / STAT PASSIVE | Categorical, fixed order: Offense / Defense / Utility |
| Second-level grouping | None | Acquisition source, in a fixed order: Native/Class, then taught routes in teaching order, then Succession victims in kill order |
| Row shape | Name + stats on one row, effect on the row beneath | Unchanged in spirit — effect still on its own indented line — but the header row's columns differ per category and a Stat Passive or class ability now shares the same row shape as everything else rather than a distinct table |
| `NEXT` column, use counters | Rendered inline | Dropped from this panel; still reachable via `/system skills <name>` |

**Classification rule, stated once so it doesn't drift per-render:** Offense deals damage, disables/restrains, or raises offensive output; Defense reduces/prevents harm, restores Health, or grants immunity to a harmful effect; Utility is everything else. A skill's effect is classified, never its name — the worked example notes Pre-empt itself renders under Utility at D-Rank (avoids losing an action) and under Offense at S-Rank (First Blade, an active initiative edge), because the Rank-driven effect changed category even though the skill did not change name.

## What did not change

**No skill is re-derived, re-Ranked, re-mastered, or re-classified in stored state.** `skills_known` entries are untouched; this migration touches only how a Runtime lays them out when the panel is called.

**No other panel's grammar changes.** `/system`, `/system gear`, `/system quests`, `/system titles`, `/system shop`, `/system log`, and `/system all`'s composition are all unaffected — Section 15.3.1 alone was ruled on.

**Section 7.1's acquisition routes, Section 7.4's mastery mechanics, and Section 7.6's Succession rules are byte-identical.** This migration reads their output; it authors none of it.

## Migration procedure

This edge **transforms no stored state.**

**1. Advance `profile_version` to 1.113** on the campaign's live character sheet, and re-pin `world_rule_profile:` in `090_CAMPAIGN_STARTUP.md`. This is the only touched state path.

**2. No skill already held is re-derived, re-grouped in storage, or re-tagged.** `skills_known` order, Ranks, mastery levels, counters, and acquisition routes are exactly as recorded. The new grouping is computed at render time from existing fields (`acquisition_route`, `taken_from`, effect text), never stored.

**3. A capture restored across this edge runs step 1 only.**

**Immutable checkpoints are byte-unchanged.**
