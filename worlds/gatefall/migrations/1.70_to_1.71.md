## What 1.71 changed

**One annotation, describing a gap that had already been closed.**

Section 11.2's boss-drop table read:

```text
| 81-90 | **Instant-dungeon key** at the Gate Rank (Section 17, authored later). |
```

*"Authored later"* was written when Section 17 did not exist. It has existed for many versions and now authors instant dungeons in full — a key's Rank and its three sources, opening, the two-hour clock, population, loot, the mineable deposit, both closing conditions, and the unregulated-space rule. The marker had been pointing at a hole that was filled long ago.

The annotation is removed and the cross-reference to Section 17 kept. **No drop, Rank, probability, table row, or rule moves.**

**Why this is a version rather than a silent edit.** Profile 1.66 established the principle when it corrected three stale self-annotations in the Section 7.3 ladders: an annotation is not a rule, but an annotation that stops matching what it describes is exactly the defect `F-013` and `F-014` recorded, and a profile that edits those quietly has no record that the description ever drifted. The same reasoning applies to a cross-reference: it is a claim about the corpus, it stopped being true, and nothing noticed.

**It is the first live instance found of the class `F-024` names.** That flag recorded a Rank rule governing a key category no section created, and its open question was whether a profile can be checked for claims that quietly stop matching its contents. This marker was turned up by a phrase grep for promissory language — *"authored later"*, *"at authored thresholds"*, *"at higher tiers"*, *"to be authored"* — run while scoping what a deferral registry would cost. It is the one-line version of the detector that flag still asks for, and it found something on its first run.

**What that grep also showed, and why the registry is still worth building.** Most hits in this profile are **legitimate and load-bearing**: Section 4.4's authoring clamp does not merely say a rung is unauthored, it holds the rung, renders `rung unauthored` in the `/system` panel, and withholds the ascension offer. That is deferral done correctly — named, mechanised, and surfaced. The registry's job is to make every deferral look like that one, and to fail the ones that are only a phrase.

## Migration procedure

**Compatibility treatment, 1.70 → 1.71.** Preserve every stored value and all resolved canon.

**1. Advance `profile_version` to `"1.71"`.**

**2. Nothing stored changes, and nothing is recomputed.** No pool, Stat, level, XP, Rank, skill, mastery, counter, title, item, key, gold, cash, quest, class, or candidate is touched. The edit removes two words from a table cell's parenthetical.

**3. Nothing retroactive.** No boss drop resolved under any earlier profile is re-rolled, and no key already held changes Rank, source, or behaviour. The `81-90` result has always meant an instant-dungeon key at the Gate's Rank and still does.

**4. No campaign owes a re-audit.** Nothing read this annotation at resolution time; it was a note to the reader, and the section it pointed at was already authoritative.

Record adoption as a campaign Event at the adopting campaign's current anchor; consume no fictional time and reopen nothing. Immutable Profile 1.70-and-earlier checkpoints remain byte-unchanged and run the compatibility chain through 1.71 at readiness.
